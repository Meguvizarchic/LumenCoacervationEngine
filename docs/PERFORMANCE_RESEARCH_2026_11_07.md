# 渲染性能调研（2026-11-07）

本轮用 Exa 调研了 RuntimeEffect / AGSL 程序复用、PSO 与离线编译、离屏纹理复用、每帧材质与采样决策
的批处理，并对照 `lumen-engine` 现状给出可落地建议。全部结论附来源链接并标注
【已验证】/【理论】/【传闻】，完整报告见会话研究副本。**本文档只是调研记录，不含本轮代码改动。**

## 主要缺口（按收益排序）

1. **`DirectSurfaceProgramApi33` 的 `RuntimeShader` 仍每绑定一份。**
   API 33+ 上每个增强表面首帧多付约 1.1–1.5 ms 的 AGSL 编译；三段透镜程序已经共享，直接着色路径
   应对齐同一策略（按参数键复用）。这是本轮识别出的最大单点收益。
2. **直接着色路径没有预热。** 透镜共享那条路径有预热，直接着色没有；首次进入页面会集中出现编译尖峰。
3. **API 31 低端机的模糊能力没有运行时探测。** 目前按版本门控，没有按设备实际能力回退，
   低端 API 31/32 设备可能落到不支持的路径。
4. **API 32+ 玻璃每帧重录。** 与「共享 GPU 内容正常重录且尺寸/采样倍率不变时继续引用同一内容节点」
   的既有结论相关，需复核是否有可合并的重复重录。
5. **Prism 饱和度可以折进 AGSL**，省一趟 pass。

## 明确不做（与仓库约束冲突）

- Impeller 式 PSO / 离线着色器编译：本引擎跑在 HWUI 之上，拿不到 PSO 层。
- 自研 GL/Vulkan 模糊：与「支持 API 27+、软件 Canvas 回退、不引入额外依赖」冲突。
- `Bitmap.Config.HARDWARE` / `HardwareBufferRenderer` 通用路径：版本与设备门控成本高于收益。
- 反射访问 HWUI 内部缓存：Android 17 起 `static final` 与内部字段访问受限，且非公开契约。

## 模糊相关的平台事实（已验证）

- `RenderEffect` 仅 API 31+ 且仅硬件画布；软件路径必须回退。
- sigma 与半径换算：`sigma = 0.57735 · r + 0.5`。
- Skia 对大半径内建降采样（`kMaxLinearSigma = 4`，对应半径约 27），超过该半径继续加大不会更模糊；
  本仓半八度 8 档的划分方向与此一致。

## 验证方式

上述缺口目前都还只是调研结论，没有实测数据。落地时按仓库既有做法处理：先补 JVM 契约测试锁定
行为，再用设备基准（`ChromeLensSharingBenchmarkTest` 那类「基线与改动交替多轮 + 窗口像素哈希
逐个相同」协议）证明像素等价与收益，最后写回 CHANGELOG。
